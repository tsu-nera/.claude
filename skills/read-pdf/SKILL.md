# PDF を読む

テキスト抽出で足りるか、ページを見る必要があるかを最初に切り分ける。これを飛ばすと
「読めなかった」と誤報告するか、表の列がずれたまま設計判断の根拠にしてしまう。

## 手順

1. **ローカルに無ければ落とす。** `WebFetch` に PDF の URL を渡すと変換には失敗するが、
   実体をローカルへ保存してそのパスを結果末尾に出す。`curl -sSL -o FILE URL` でもよい
2. **`pdftotext -layout FILE -`** で抽出する
3. **出力が空か数行しか出ない → スキャン PDF。** Read ツールにその PDF を
   `pages: "1-5"` 付きで渡し、ページを画像として読む。テキストが無いだけで内容はある
4. **長い文書は全文を読まない。** `pdftotext -layout FILE FILE.txt` に落とし、
   `grep -n` で当たりを付けて `sed -n 'A,Bp'` で窓を切る

## 落とし穴

- **`-layout` を外すと表の列が混ざる。** 帳票・数表は元の桁位置が唯一の手掛かりなので
  必須。逆に段組みのない散文は素の `pdftotext` の方が読みやすい
- **`-layout` でも罫線とセル結合は消える。** 見出しがどの行に掛かるか曖昧なときは
  Read でそのページを見て確かめる。テキスト側の見た目で決めない
- **ヘッダ・フッタ・ページ番号が本文行に混ざる。** 邪魔でも消さない。行番号がずれて
  `grep -n` → `sed -n` が狂う
- **10ページ超の PDF は Read に `pages` 指定が要る**（1リクエスト20ページまで）
- **OCR (tesseract) は無い環境がある。** スキャン PDF のテキスト化に頼らず Read で読む
- **帳票だけ切り出した PDF には教示が付いていない。** 空欄の様式から仕様を推測すると、
  なぜその粒度なのかを取り違える。本文が別ファイルなら本文も取る
