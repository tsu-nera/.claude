# リサーチ

## 進め方

- 観点ごとのクエリを1ターンで並列に投げ、メインモデル自身が結果を読む。検索を小モデルの subagent に投げて短い要約で受け取ると、日付・数値・主張と出典の対応が落ち、結局検証し直すことになる。
- Agent を使うのは、多数のページ本文を読み込む深掘りでメインの context を守りたい時だけ。その場合も要約ではなく「主張・根拠の引用・URL・公開日」の形で返させる。
- ページ本文が取れない時は `read-web`、PDF は `read-pdf` スキルに従う。

## ソース選択

Web 検索で足りない時に併用する。adapter を使う前に対応する reference を読む（クエリ構文と品質フィルタに落とし穴がある）。

- **実装手順・エラー解決・日本語の詰まりどころ**: Qiita → `references/qiita.md`
- **個人開発・検証記事・定番記事（いいね順が効く）**: Zenn → `references/zenn.md`
- **障害・サービス状況・速報**: `x-research` スキルに委譲

## 報告で守ること

- 検索スニペットだけを根拠に断定しない。結論を支える主張は本文を開いて確認し、開いていないものは「未確認」と書く。スニペットは要約が古い・切り取りで逆の意味になることが多い。
- 情報の公開日・更新日を添える。半年以上前の情報が結論を左右するなら、その旨を書く。製品・API・価格は変わりやすい。
- 一次情報（公式ドキュメント、リリースノート、論文、当事者の発表）を二次記事より優先し、両者が食い違えば両方示す。
- 出典は主張の近くに置く。末尾にまとめるだけだと、どの主張がどの URL に依るか読み手が追えない。
